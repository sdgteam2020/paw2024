Important distinction
---------------------
The complete wwwroot directory is not the same as a browser page payload. It includes downloads, uploaded PDFs, alternate library builds, source maps, development files, and assets for unrelated routes.

The exact individual artifact exceeding 7 MB is:

  swas.UI/wwwroot/PDF/SOP on Whitelisitng of Appl Sw in IA dt 28 May 24.pdf
  Size: 7.59 MB

If this PDF is downloaded or embedded by the target page, it alone exceeds the 7 MB threshold. A page target below 4 MB therefore requires that it not be part of the initial page payload, or that it be replaced/compressed separately.

Duplicate libraries and assets
------------------------------
Bootstrap appears under multiple locations:

  wwwroot/lib/bootstrap
  wwwroot/assets/css/bootstrap.min.css
  wwwroot/assets/dataTable/css/bootstrap.css
  NuGet Bootstrap content files

The shared layout loads both assets/dataTable/css/bootstrap.css and assets/css/bootstrap.min.css. Their functional overlap should be reviewed before removing either one.

jQuery appears in multiple locations:

  wwwroot/assets/js/jquery.min.js
  wwwroot/Content/jquery-3.6.0.min.js
  wwwroot/lib/jquery/dist/jquery.min.js
  wwwroot/jquery

DataTables-related files are duplicated between wwwroot/assets/dataTable, wwwroot/css, and wwwroot/js.

PDF export files are duplicated:

  assets/dataTable/js/pdfmake.min.js
  js/pdfmake.min.js
  assets/dataTable/js/vfs_fonts.js
  js/vfs_fonts.js

The two vfs_fonts.js files are identical and together occupy approximately 1.66 MB.

Font Awesome contains multiple full CSS, JavaScript, sprite, SVG, font, LESS, and SCSS variants under both font-awesome and assets/css/font-awesome.

Unused asset limitations
------------------------
A definitive unused-asset list cannot be established from static inspection alone because Razor views and JavaScript may build URLs dynamically, uploaded PDFs may be referenced by database values, and authorization can change which assets are requested.

The following are strong candidates for runtime verification:

  - duplicate Bootstrap builds
  - duplicate jQuery builds
  - duplicate DataTables files
  - duplicate pdfmake and vfs_fonts files
  - source maps
  - Font Awesome source files and unused icon families
  - unused RTL and ESM builds
  - PDF.js assets on non-PDF pages
  - country-flag HTML assets
  - old or oversized GIF animations
  - demo/template images under cards, carousel, products, and similar-products

Recommended safe optimization plan
-----------------------------------
No optimization was applied during this investigation.

Recommended order after approval:

  1. Capture the actual browser Network request list for the target route.
  2. Separate initial page resources from lazy-loaded resources and downloads.
  3. Load PDF.js only on pages that display PDFs instead of loading it in the shared layout.
  4. Load Chart.js, DataTables export, JSZip, and PDFMake only on pages that use them.
  5. Remove only verified duplicate files after source and runtime coverage checks.
  6. Exclude source maps and development-only assets from production publishing.
  7. Optimize large GIF and PNG files after checking displayed dimensions and visual quality.
  8. Enable Brotli or gzip compression for HTML, CSS, JavaScript, SVG, and JSON.
  9. Keep large PDFs as downloads or lazy-loaded resources rather than initial page resources.
 10. Repeat the same browser capture and verify the resulting page is below 4 MB.

Safety constraints
------------------
The proposed work can be limited to static asset delivery and production publishing. It must not change:

  - existing functionality
  - UI behavior
  - business logic
  - API calls
  - routes
  - database operations

Conclusion
----------
The exact 7 MB artifact is the 7.59 MB PDF named above. The page-level payload is also inflated by globally loading PDF.js, its 3.10 MB worker, PDFMake fonts, Chart.js, DataTables extensions, and several duplicated libraries. The most likely path to below 4 MB is route-specific loading plus removal of verified duplicate/development assets, image optimization, and HTTP compression. No application code was changed during this analysis.
