 PAW PHASE 3A - DASHBOARD NETWORK PAYLOAD INVESTIGATION
Investigation only. No files modified or deleted.

Scope: swas.UI Home/Index dashboard.

1. PDF/EXPORT DEPENDENCIES

References:
- swas.UI/Views/Home/Index.cshtml:363 includes _DataTablesExportScripts.cshtml.
- swas.UI/Views/Shared/_DataTablesExportScripts.cshtml loads jszip, pdfMake, vfs_fonts, buttons.html5, and buttons.print.
- swas.UI/wwwroot/DeveloperJs/CommanDatatable.js configures DataTables export buttons.
- swas.UI/Views/Home/Index.cshtml:360 includes _whitelistdProjectView, which is part of the dashboard response.

Current behavior:
The export partial loads during the initial dashboard response. PDF/export assets are not needed to render the four dashboard charts, but they are available for DataTables export interactions.

Measured uncompressed sizes:
- wwwroot/js/pdfmake.min.js: 1,440,431 bytes.
- wwwroot/assets/dataTable/js/vfs_fonts.js: 870,289 bytes.
- wwwroot/assets/dataTable/js/jszip.min.js: 117,910 bytes.
- wwwroot/assets/dataTable/js/buttons.html5.min.js: 24,052 bytes.
- wwwroot/assets/dataTable/js/buttons.print.min.js: 2,091 bytes.
- Total export group: 2,454,773 bytes (~2.34 MiB).

Network finding supplied: pdfMake ~828 KB and vfs_fonts ~574 KB. These are consistent with transfer/compression differences from the uncompressed file sizes.

Recommendation:
Lazy-load the export group only when an export/print button is clicked, after confirming all dashboard and partial DataTables are initialized without those libraries. Load order must remain: jszip before Excel export, pdfMake and vfs_fonts before PDF export, then HTML5/print button modules. This is a strong candidate for initial-network savings.

Risk:
Removing the partial from initial markup without replacing the button initialization can break export buttons. No implementation was made.

4. DASHBOARD API PAYLOADS

GetDashboardCount:
- UI: swas.UI/wwwroot/DeveloperJs/Dashboard.js:31-64.
- Controller: swas.UI/Controllers/HomeController.cs:381-394.
- Service/repository: swas.BAL/Interfaces/IProjStakeHolderMovRepository.cs and swas.BAL/Repository/ProjStakeHolderMovRepository.cs:361-550.
- SQL: dbo.usp_DashboardCount.

The repository reads eight result sets into DTODashboard:
- dtoDashboardCountlst
- dtoDashboardCountlstForAction
- dtoDashboardHeaderlst
- dtoApprovedCountlst, populated from multiple result sets

Dashboard.js consumes header stage/status fields, count status/stage/count fields, action actionId/stagesId/tot/isComplete fields, and approved status/is_AI_ML/statusActionsMappingId/total fields. Some serialized fields appear unnecessary to this client path, including several DTO fields such as ProjId and some display/status fields in approved-count rows; this requires response-shape testing before removal.

Recommendation: Measure per-result-set row counts and JSON contribution in Chrome/server logs. Consider purpose-built count DTO projections and avoiding unused fields, but preserve all result sets and dashboard click behavior until verified.

GetProjCommentsByUnitId:
- UI: swas.UI/wwwroot/DeveloperJs/ProjectstkholderComments.js:212-268 and table binding at 291 onward.
- Controller: swas.UI/Controllers/ProjectsController.cs:1832-1844.
- Repository/service: swas.BAL/Interfaces/IProjComments.cs and swas.BAL/Repository/ProjComments.cs:29-80.
- SQL: usp_GetAllStkForComment.

DTO fields such as Attpath, ActFileName, Comments, Date, UserDetails, UpdatedByUserId, StkCommentId, and UnitId are not observed in the primary table binding. Some cached/secondary code paths use status/comments, so these must not be removed without tracing the complete file and all response consumers.

The stored-procedure definitions were not present in the repository SQL file, so SQL column-level savings cannot be confirmed from source control.

Recommendation: Obtain the deployed procedure definitions or SQL execution plans, then create a minimal response projection only after validating every consumer and export/detail path.

5. BROWSER LINK / REFRESH

Repository search found no explicit browserLink or aspnetcore-browser-refresh.js references in Razor, JavaScript, C#, or configuration.

Program.cs uses app.UseStaticFiles() and does not show application registration for Browser Link. launchSettings.json sets ASPNETCORE_ENVIRONMENT=Development for local profiles. The scripts are therefore likely Visual Studio/development tooling injection rather than application-owned static dependencies.

Production behavior:
They should not be injected by the application in a non-Development deployment. Confirm with a published/production response and with Chrome Network Disable cache enabled. Do not change application files based only on a development response.

Recommendation: Treat Browser Link and browser refresh assets as development-only. Verify production HTML and response headers; no production savings are claimed from repository assets.

6. CHARTS AND DATATABLE EXPORT INITIAL LOAD

Chart dependencies:
- Home/Index.cshtml loads chart.min.js and chartjs-plugin-datalabels.js.
- Dashboard.js creates four dashboard charts and registers ChartDataLabels for them.
- chart.min.js: 229,330 bytes.
- chartjs-plugin-datalabels.js: 16,080 bytes.
- Initial chart group: 245,410 bytes.

Recommendation: Keep both on initial dashboard load. They are required by the four visible charts. They could only be deferred if charts themselves are deferred, which changes initial UI timing and requires explicit product approval.

DataTables/export:
- Home/Index.cshtml loads the export partial initially.
- The dashboard includes tables/modals and commandatatable.js, so DataTables core/layout dependencies remain relevant.
- Export-specific jszip, pdfMake, vfs_fonts, HTML5, and print modules are not needed until export/print is invoked and are the primary lazy-load candidates.

INITIAL NETWORK SAVINGS

High-confidence candidate: defer the export group: approximately 2,454,773 uncompressed bytes, or the observed compressed transfer equivalent (~828 KB pdfMake plus ~574 KB vfs_fonts plus remaining export modules).

Not counted as safe initial savings:
- Bootstrap styles: different versions/roles and broad usage.
- Chart.js/datalabels: required for four visible dashboard charts.
- loadsss.gif: shared layout asset.
- flow.png: used by workflow/detail views.
- Browser Link/refresh scripts: tooling-dependent and not repository-owned.

TOTAL WWWROOT/PACKAGE SAVINGS

Potential static file/package savings are not the same as initial network savings. No files are proposed for deletion in this investigation. The export group occupies 2,454,773 bytes uncompressed, but retaining it for lazy loading produces zero package savings and only defers initial transfer. Image optimization savings are unmeasured. Bootstrap consolidation savings are unproven.

STATUS AND APPROVAL GATE
